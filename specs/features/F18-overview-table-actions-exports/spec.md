# F18 · Overview III: Pipeline Table Parity, Row Actions, Exports

## Context
This brings the batch table to parity with the as-built "Pipeline — Exceptions First" table: the 20-column set with a column chooser, a toolbar with three exports, search-all with highlighting, pagination, exception row styling, a material cell with tags, bookmarks, keyboard navigation, and the **row actions Place Hold and Release on COA**. Those actions are the only new domain behaviour.

## Functional requirements
| ID | Requirement |
|---|---|
| F18-FR-01 | **Shared `DataTable`** (TanStack Table v8). It provides sortable headers with arrows, a filter box beneath each filterable header (always visible, parity), client-side pagination (« ‹ Prev, Page x of y, Next › », rows per page 25/50/100, default 50), a toolbar repeated at top and bottom, and `Reset Table` (clears sort and column filters only). It is used by the Overview and by every list window (F16, F19, F20, F21) |
| F18-FR-02 | **Columns:** 20 available, 16 on by default, in this order: Material · Campaign · Class · Batch · Lot # · Inbound · Deviation · Location · Stage · `System Needs-By` · Adjusted Date · SLA Deadline · Next Inspection · Days In Stage · Status · Expected Completion. Hidden by default: First QC Date (`qc_testing_entry`), Goods Receipt Date, `<terms.lims>` Approved Date, Usage Decision Date. A **Columns** panel lists all 20 as a checklist, with `Reset` at the top. The choice persists per user in `sessionStorage`. Horizontal scroll, with the first column sticky |
| F18-FR-03 | **Cells:** (a) **Material:** star ☆/★ (bookmark), bold code, description beneath, supplier batch muted beneath that, tag chips (05 v2 colours), and a `⋯` actions button. (b) **Batch:** link that opens Batch History (F19; until then, the F11 drawer). (c) **Inbound/Deviation:** clickable 8 px dots (green, amber, red, grey; amber inbound = resolved, see F19), opening F19 windows. (d) **Stage:** coloured badge. (f) **SLA Deadline:** the current stage's `must_complete_by` with a RAG dot. (g) **Next Inspection:** `next_inspection_date`. (h) **Status:** `LATE +Nd` in red when late (N = days overdue), `DUE IN Nd` in amber when amber, `ON TRACK` in green otherwise, `—` for terminal or pending rows. The speech-bubble icon and the latest status-log comment are added in F19, so render them only when `latest_status` is present. (i) **Expected Completion:** date, or `17 Aug 2026 (56d over)` with the whole cell red when overdue |
| F18-FR-04 | **Exception styling:** rows that are late, rejected, on hold or air-gap (exactly the exception groups of 03 §5.5; ERP-blocked is shown by its tag only) get the tinted background and 3 px red left bar, and sort first (existing exceptions-first order) |
| F18-FR-05 | **Search all columns…** filters across every visible column's displayed text as you type (case-insensitive), updates the count, and **highlights every match** with `<mark>`. An × clears it. URL `q` (existing). Highlighting is client-side |
| F18-FR-06 | **Count:** `1–50 of 482 lots (n batches)` (in-flight lots only, F17-FR-10; supersedes the earlier 803 caption) beside the search box, and `No results` when empty |
| F18-FR-07 | **Exports** (CSV, via `fetch` + blob with the persona header): `Export ▾` offers **This page (n rows)** and **All filtered results (n rows)** with the visible columns. **Export Sampling Plan:** rows at `sampling`, honouring the filters, columns `material_no, material_desc, batch_no, lot, location, operative_need_by, expected_completion, days_in_stage, tags`, sorted exceptions-first. **Export QC Testing Queue:** rows at `qc_ship` or `qc_testing`, columns `material_no, batch_no, lot, sample_id, offsite, external_lab, stage, stage_entry, expected_completion, operative_need_by, tags`. Server endpoints `GET /api/export/{table|sampling-plan|qc-queue}.csv`. The existing `/api/export.csv` stays as an alias of `table`. The stage sets for the two queue exports come from a new profile block `exports: {sampling_plan: [sampling], qc_queue: [qc_ship, qc_testing]}` |
| F18-FR-08 | **Row actions** (`⋯` menu): **+ Place Hold** / **Release Hold**, and **Release on COA** / **Undo Release on COA**. Roles: hold for `planner`, `qa_release` and `admin`; Release on COA for `qa_release` and `admin`. Others see disabled items with "Read-only role" (demo RBAC; the as-built had no check, and the governance story is stronger with one). Each action asks for a short reason (required) and writes a versioned override plus an audit event (`hold_placed`, `hold_released`, `coa_release_set`, `coa_release_cleared`) |
| F18-FR-09 | **Place Hold semantics:** displayed `on_hold = erp_hold OR manual_hold`. A manual hold adds the ON HOLD tag, counts on the On Hold card and in the ON HOLD filter, and sorts as an exception. **The plan maths is unchanged** (the clock is not frozen in Tier 1). Released rows cannot be held (409) |
| F18-FR-10 | **Release on COA semantics:** when set, the row's plan uses the profile `release_on_coa.sla_days` (site_a 14) **from `cycle_start_date`** as the single deadline for release. `expected_completion` = cycle start + 14 days, RAG and late follow, and no compression applies. The tag reads RELEASE ON COA. Implemented in `r2r_core.sla.plan(..., coa_release: bool)` with 100% branch coverage kept. Not allowed on `released` rows (409) |
| F18-FR-11 | **Keyboard:** Tab focuses the table, ↑/↓ moves the row focus ring, Enter opens Batch History, B toggles the bookmark. These are announced in a small "Keyboard" hint under the table |
| F18-FR-12 | Remove F10's virtualised table (replaced by pagination), keeping F10's live-update highlight and "Updated just now" toast |

## Contract changes
- **03 §2 profile:** `release_on_coa: {sla_days: 14}`. **03 §5:** a COA-release plan rule and display-only manual hold (§6 flags: `on_hold` becomes `erp_hold OR manual_hold` at read time; rename the published flag to `erp_hold`, or keep `on_hold` as the ERP flag and add `on_hold_display` in the API, whichever is the smaller change; record it). **Decided:** keep the published `on_hold` (= ERP hold). The API adds `manual_hold` and `on_hold_display = on_hold OR manual_hold`, and `Flags(on_hold=on_hold_display)` drives sorting, the On Hold card and the ON HOLD filter.
- **04 §1.1:** `mcha.qnext` date (next inspection; datagen fills it for released drug substances with release + 12–24 months, and for re-eval stories). **04 §3/§4.1:** `next_inspection_date`.
- **04 §5:** override fields `manual_hold` (`{"on": bool, "reason": str}`) and `release_on_coa` (`{"on": bool, "reason": str}`).
- **F09:** `POST /api/rows/{row_key}/hold`, `/coa-release` (body `{on, reason}`), and the export endpoints.

## Acceptance criteria
- **F18-AC-01** The default view shows the 16 columns in order. Turning on "Goods Receipt Date" in Columns adds it, and Reset restores the 16.
- **F18-AC-02** Searching "B20" narrows the table, highlights matches in Batch, and updates the count. × clears it.
- **F18-AC-03** As Alex, Place Hold on a non-story sampling row with reason "Awaiting supplier confirmation". It gains the ON HOLD tag, On Hold rises by 1, the row sorts into the exception block, and the audit log has `hold_placed`. As Sam, the menu items are disabled.
- **F18-AC-04** Unit fixture: `plan(coa_release=True)` for a sampling row with cycle start 2026-10-05 gives expected 2026-10-19. As Alex on the live stack, Release on COA on any sampling row gives expected = its cycle start + 14 days and the tag RELEASE ON COA. Undo restores the previous plan. Unit tests cover `plan(coa_release=True)` cases (on track, late, with need-by present).
- **F18-AC-05** Export Sampling Plan downloads a CSV whose row count equals the sampling rows under the current filters. The QC queue likewise.
- **F18-AC-06** Keyboard: Tab, then ↓↓, then Enter opens the third row's history. B toggles its star.
- **F18-AC-07** Late rows show `LATE +Nd` and a red Expected Completion with `(Nd over)`. A row due in 2 days shows `DUE IN 2d` in amber.
- **F18-AC-08** Screenshot `docs/screenshots/overview-table.png` at 1440×900. Overview p95 is still < 300 ms server-side.
