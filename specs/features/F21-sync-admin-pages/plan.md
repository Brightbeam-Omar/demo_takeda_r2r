## Deviations
- **`run_seq` in `pipeline_runs_v` (T2).** The demo clock does not tick, so two runs on the same demo day have the same `started_at` and the page could not tell which is newer. `pipeline_runs_v` therefore carries `run_seq` (wall-clock microseconds of the run's setup step, written by `run_step` into the log's `detail_json` as `wall_us`). Recorded in 04 §4.2d.
- **Where the comparison lives (T2).** `snapshot_aggregate` computes `row_hash` and counts `inserted` against `intelligence.row_hash_last`, but `publish` rewrites `row_hash_last` after the last object is written, so a run that fails after the snapshot step never moves the baseline (OQ-129). The hash itself is computed with the `row_hash()` macro in DuckDB over the snapshot table.
- **Latest run in its own history (T2).** `publish` builds `pipeline_runs_v` before `notify` exists, so the latest run's steps stop at a synthetic `publish` row and its duration excludes publish's tail and notify; the next publication shows the full run.
- **"Full pass" (T3).** The worker wakes every 2 s, beats the heartbeat and drains `pending` events; every `DRAIN_INTERVAL_SECONDS` the wake is a **full pass**, which also takes back stale claims (OQ-130, OQ-131). A full pass does not re-sync the latest run when no event is queued: an event-less re-sync is the safety poll of T2-02, which would write `source=poll` rows, and the page shows that card as 0 with a T2-02 tag until it exists.
- **Endpoints (T3).** `GET /api/sync/health` (the six cards), `POST /api/sync/run-pipeline` (admin) in `routers/webhooks.py`; `GET /api/pipeline/runs` and `/runs/{id}/steps` in `routers/runs.py`; `STALE_CLAIM_MINUTES` moved to `sync/limits.py` so the API imports no lakehouse code (F08-AC-07).
- **`duration_ms` in `pipeline_run_steps_v` (T4).** The demo clock does not tick, so a step's `started_at`/`finished_at` are equal and a duration cannot be derived from them. The view carries the step's real `duration_ms` (from the log's `detail_json`). Recorded in 04 §4.2d.
- **DataTable `expansion` prop (T5).** The event list needs a detail line under an expanded row (drain pass, claimed/finished ages, error). `DataTable` gained an optional `expansion(row)` that returns the content while the row is expanded, or null; the page owns the expanded set. No other table changed.
- **Routes (T4/T5).** Sync Status, Webhook Sync Status and Audit Log live at `/admin/sync`, `/admin/webhooks`, `/admin/audit`; the old `/sync`, `/sync/webhook` and `/audit` redirect (F21-FR-07, OQ-135). The F11 `Sync` page and its test are removed.
