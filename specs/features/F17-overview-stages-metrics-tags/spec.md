# F17 · Overview II: Stage Cards (incl. Expected Delivery), Metric Cards, Tag Row

## Context
This brings Pipeline by Stage, Weekly Metrics and the tag row to parity (05 v2 §4 (3)–(6)). It also adds the one new data object these need: **expected deliveries** (open purchase-order lines). They are a pre-batch grain shown as "Stage 0", never added to the pipeline total.

## Functional requirements
| ID | Requirement |
|---|---|
| F17-FR-01 | **ERP open PO lines (source):** new erp_sim table `ekpo` (`ebeln` text, `ebelp` text, `matnr`, `lifnr`, `eindt` date (scheduled delivery), `menge` numeric(13,3), `lgort` (planned receiving location), `is_open` bool, `updated_at`), PK (`ebeln`, `ebelp`). Events: `POST /events/po-line-created` and `/events/po-line-closed`. `goods-receipt` accepts an optional `ebeln/ebelp`, stores them on the `101` `mseg` row (new nullable columns, OQ-092) and closes that line; a same-day `goods-receipt-reversal` **reopens** the line of the `101` it nets; a GR without a PO reference reopens nothing. Numbers: `ebeln` 10 digits starting `45`, `ebelp` `00010` steps |
| F17-FR-02 | **Datagen** (new `rng.stream(seed, "po_lines")` so existing draws are unaffected): every batch's GR is preceded by a PO line created 2–8 weeks before, and closed by the GR. Lines reopened by reversed receipts count as overdue. Future lines for existing materials and suppliers bring the open total at demo start to 60–90, about 10% of them overdue (`eindt` < today, still open) (OQ-093). Determinism and the agreement test are unaffected. **The F05 report counts (803/650/482/321) and the week-41 percentages must not change** |
| F17-FR-03 | **Pipeline:** extract `stg_ekpo`. Publish `expected_deliveries_v` (04 §4.6: `ebeln, ebelp, material_no, material_desc, molecule_type, material_class, supplier_id, supplier_name, campaign, scheduled_date, quantity, planned_location, planned_location_type, overdue bool, run_id`). The grain is the open PO line. Mirror `mirror_expected_deliveries`. Add it to the F08 consistency rules (it carries `run_id`) |
| F17-FR-04 | **Stage cards:** in this order: **Stage 0 Expected Delivery** (dashed border, count = open lines with `scheduled_date ≤ to` for a period, matching 03 §5.6, or all open lines under All Dates; caption "Open PO lines" under All Dates and "Due this period" otherwise; type and class filters apply via the material, campaign via its earliest open demand, and stage, tags and bookmarks never apply, OQ-094), **All Stages · Total Pipeline** (open rows, caption "Active batches"), then one card per profile stage with `show_card != false` in sort order, labelled `STAGE n` (n counting from 1 over visible stages), with **▸ arrows** between them, then a divider and **On Hold** (amber, ⚠, caption "Frozen batches"). Add `show_card: false` for `pending` in site_a (still counted in the total and filterable via the table), and publish `show_card` in `stage_reference_v` and its mirror, because `/api/reference` reads the mirror. Each stage card shows its count, `SLA n d`, and `N late` in red when > 0 (F10 behaviour kept). Any card whose stage has an `applies_if` shows a green note "N skip <label>": open rows (not released) past that stage's position for which `applies_if` is false (site_a: "N skip call-off" on Call Off and the same note on QCL Ship). The API returns a generic `skip_count` on every flow entry whose stage has `applies_if` (null otherwise); it honours every filter except stage (OQ-095). No stage key is hard-coded. Released has no late count |
| F17-FR-05 | **Multi-select:** clicking a stage card toggles it in a stage set. Total Pipeline is selected by default and deselected when any stage is selected. Selected cards get the lavender tint and indigo outline; the rest stay grey. The header gains `[✕ Clear N stages]`. Selections appear as chips (F16). The URL repeats `stage=` per selected stage (OQ-059 repeated-param style), and F09 accepts multiple values additively. **Selecting filters the table, not the cards.** Clicking Expected Delivery opens an **Expected Deliveries window** (PO, line, material, supplier, scheduled date, quantity, planned location, overdue chip) |
| F17-FR-06 | **Metric cards** per 05 v2 §4 (4). Header `Week <iso week> (<year>) — <n> R2R Metrics` for the last complete period, with the week taken from the published `week_start` (no client-side week maths beyond formatting), plus `Source: weekly_metrics_v` in monospace. Each card: `METRIC n` (n = id number), name, big %, then `<sla> · on_time/completed` with ⓘ (tooltip: how it's computed and the source view; the F11 Explain popover is reachable from the % itself). A 4 px top bar: green if ≥ green threshold, amber if ≥ amber, red below, none if N/A. N/A cards read `N/A` with the `null_reason` in the ⓘ tooltip (until T2-01). Keep the sparkline (small, beneath) as a demo addition. No `4-wk` label in Tier 1 (T2-01 adds `window_weeks`). The SLA reads `SLA 7d`, with the re-eval variant in the tooltip. The header shows the ISO week and ISO week-year of `week_start` (OQ-098) |
| F17-FR-07 | **Showing line** above the tag row: `Showing: All in-flight batches`, or a summary of the active stage, tag and bookmark selection (e.g. `Showing: 3 stages selected · 2 tags`) |
| F17-FR-08 | **Tag row** per 05 v2 §2 colours: `ALL, LATE, ON HOLD, REJECTED` (REJECTED = `ud_rejected` OR `lims_rejected`), then `RE-EVAL, EXPEDITE, FULL SPEC, OFFSITE TEST, RELEASE ON COA, <terms.erp_blocked_tag>, AIR GAP, RELEASED`, then `Clear tags`. Multi-select is OR across tags (the guide's semantics; F09 `flags[]` is already OR). Selected tags fill solid and ALL switches off. RELEASED shows released rows and is equivalent to selecting the Released card (FR-10). Tags are OR among themselves and AND with stage and the other filters. ON HOLD queries the current `on_hold`; F18 re-points it to `on_hold_display`. The tag row also accepts `release_on_coa`, which returns zero rows until F18 (OQ-097). RELEASE ON COA is wired in F18 and shows zero until then. The tags also render under the material code in rows (F18) |
| F17-FR-10 | **In-flight default (OQ-096):** the default table shows in-flight lots only, meaning not released (pending included), matching "Active batches" on Total Pipeline. Released rows appear only when the Released card is selected or the RELEASED tag is active. `GET /api/overview` takes `include_released` (default false) and treats a `released` stage or flag as true; `GET /api/export.csv` follows the same default. The response gains `batch_count` (distinct `(material_no, batch_no)`), and the toolbar reads `… of 482 lots (n batches)` at demo start. F09, F10 and F16 tests and specs that assumed 803 are updated; this supersedes the earlier "803 lots" caption |
| F17-FR-09 | **Remove F10's alert-chip band** (moved from F16-FR-10, OQ-085), in the same PR that adds the LATE, REJECTED and ON HOLD tags, together with F10's inline tag chips that the tag row replaces. Late, rejected and on-hold counts are then reachable only through those tags and the stage cards' late counts |

## Contract changes
- **04 §1.1:** the `ekpo` table and events. **04 §4:** `expected_deliveries_v`. **04 §5:** `mirror_expected_deliveries`.
- **03 §2:** stage `show_card` (default true); site_a `pending.show_card: false`.
- **F08:** consistency includes the new object. **F09:** multi-value `stage`, `GET /api/expected-deliveries` (filters: period), and `skip_call_off_count` on the Call Off flow entry.

## Acceptance criteria
- **F17-AC-01** At demo start (All Dates), Expected Delivery shows the open PO line count from `expected_deliveries_v`, and Total Pipeline shows 482. The two are never summed anywhere.
- **F17-AC-02** Selecting Sampling + QCL Ship + QCL Testing filters the table to those stages, and the card counts don't change. "✕ Clear 3 stages" and three chips appear, and the URL holds `stage=sampling&stage=qc_ship&stage=qc_testing`.
- **F17-AC-03** The Call Off card shows "N skip call-off", with N matching an API count test.
- **F17-AC-04** The metric cards show `Week 41 (2026)` (the last complete week before 12 Oct 2026 is ISO week 41, starting 5 Oct), with M3 94% green, M6 84% amber and M7 69% red (OQ-099), and with `on_time/completed` counts matching `weekly_metrics_v`.
- **F17-AC-05** Selecting ON HOLD + EXPEDITE shows rows carrying either one. Clear tags restores everything. The F10 alert-chip band is gone (FR-09).
- **F17-AC-06** F06 stage agreement stays at 100%, the datagen determinism test passes with the PO lines, and the F05 report counts and week-41 percentages are unchanged.
- **F17-AC-07** Screenshot `docs/screenshots/overview-stages-metrics.png` at 1440×900.
- **F17-AC-08** At demo start the default table shows 482 lots; selecting the Released card or the RELEASED tag shows the 321 released lots; the F05 counts (803 lots, 650 batches, 482 open, 321 released) are unchanged in the report.
