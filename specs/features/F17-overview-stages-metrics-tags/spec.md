# F17 · Overview II: Stage Cards (incl. Expected Delivery), Metric Cards, Tag Row

## Context
This brings Pipeline by Stage, Weekly Metrics and the tag row to parity (05 v2 §4 (3)–(6)). It also adds the one new data object these need: **expected deliveries** (open purchase-order lines). They are a pre-batch grain shown as "Stage 0", never added to the pipeline total.

## Functional requirements
| ID | Requirement |
|---|---|
| F17-FR-01 | **ERP open PO lines (source):** new erp_sim table `ekpo` (`ebeln` text, `ebelp` text, `matnr`, `lifnr`, `eindt` date (scheduled delivery), `menge` numeric(13,3), `lgort` (planned receiving location), `is_open` bool, `updated_at`), PK (`ebeln`, `ebelp`). Events: `POST /events/po-line-created` and `/events/po-line-closed`. `goods-receipt` accepts an optional `ebeln/ebelp` and closes that line, and a same-day `goods-receipt-reversal` **reopens** it. Numbers: `ebeln` 10 digits starting `45`, `ebelp` `00010` steps |
| F17-FR-02 | **Datagen** (new `rng.stream(seed, "po_lines")` so existing draws are unaffected): every batch's GR is preceded by a PO line created 2–8 weeks before, and closed by the GR. At demo start, about 60–90 open lines are due in the next 0–8 weeks (and ~10% overdue: `eindt` < today, still open). Determinism and the agreement test are unaffected. **The F05 report counts (803/650/482/321) and the week-41 percentages must not change** |
| F17-FR-03 | **Pipeline:** extract `stg_ekpo`. Publish `expected_deliveries_v` (`ebeln, ebelp, material_no, material_desc, supplier_id, supplier_name, scheduled_date, quantity, planned_location, planned_location_type, overdue bool, run_id`). The grain is the open PO line. Mirror `mirror_expected_deliveries`. Add it to the F08 consistency rules (it carries `run_id`) |
| F17-FR-04 | **Stage cards:** in this order: **Stage 0 Expected Delivery** (dashed border, count = open lines with `scheduled_date ≤ to` for a period, matching 03 §5.6, or all open lines under All Dates; caption "Due this period"), **All Stages · Total Pipeline** (open rows, caption "Active batches"), then one card per profile stage with `show_card != false` in sort order, labelled `STAGE n` (n counting from 1 over visible stages), with **▸ arrows** between them, then a divider and **On Hold** (amber, ⚠, caption "Frozen batches"). Add `show_card: false` for `pending` in site_a (still counted in the total and filterable via the table), and publish `show_card` in `stage_reference_v` and its mirror, because `/api/reference` reads the mirror. Each stage card shows its count, `SLA n d`, and `N late` in red when > 0 (F10 behaviour kept). Any card whose stage has an `applies_if` shows a green note "N skip <label>": open rows past that stage's position for which `applies_if` is false (site_a: "N skip call-off" on Call Off). No stage key is hard-coded. Released has no late count |
| F17-FR-05 | **Multi-select:** clicking a stage card toggles it in a stage set. Total Pipeline is selected by default and deselected when any stage is selected. Selected cards get the lavender tint and indigo outline; the rest stay grey. The header gains `[✕ Clear N stages]`. Selections appear as chips (F16). The URL repeats `stage=` per selected stage (OQ-059 repeated-param style), and F09 accepts multiple values additively. **Selecting filters the table, not the cards.** Clicking Expected Delivery opens an **Expected Deliveries window** (PO, line, material, supplier, scheduled date, quantity, planned location, overdue chip) |
| F17-FR-06 | **Metric cards** per 05 v2 §4 (4). Header `Week <iso week> (<year>) — <n> R2R Metrics` for the last complete period, with the week taken from the published `week_start` (no client-side week maths beyond formatting), plus `Source: weekly_metrics_v` in monospace. Each card: `METRIC n` (n = id number), name, big %, then `<sla> · on_time/completed` with ⓘ (tooltip: how it's computed and the source view; the F11 Explain popover is reachable from the % itself). A 4 px top bar: green if ≥ green threshold, amber if ≥ amber, red below, none if N/A. N/A cards read `N/A` with the `null_reason` in the ⓘ tooltip (until T2-01). Keep the sparkline (small, beneath) as a demo addition |
| F17-FR-07 | **Showing line** above the tag row: `Showing: All in-flight batches`, or a summary of the active stage, tag and bookmark selection (e.g. `Showing: 3 stages selected · 2 tags`) |
| F17-FR-08 | **Tag row** per 05 v2 §2 colours: `ALL, LATE, ON HOLD, REJECTED` (REJECTED = `ud_rejected` OR `lims_rejected`), then `RE-EVAL, EXPEDITE, FULL SPEC, OFFSITE TEST, RELEASE ON COA, <terms.erp_blocked_tag>, AIR GAP, RELEASED`, then `Clear tags`. Multi-select is OR across tags (the guide's semantics; F09 `flags[]` is already OR). Selected tags fill solid and ALL switches off. RELEASED shows released rows (otherwise excluded only when a stage set excludes them). RELEASE ON COA is wired in F18 and shows zero until then. The tags also render under the material code in rows (F18) |
| F17-FR-09 | **Remove F10's alert-chip band** (moved from F16-FR-10, OQ-085), in the same PR that adds the LATE, REJECTED and ON HOLD tags, together with F10's inline tag chips that the tag row replaces. Late, rejected and on-hold counts are then reachable only through those tags and the stage cards' late counts |

## Contract changes
- **04 §1.1:** the `ekpo` table and events. **04 §4:** `expected_deliveries_v`. **04 §5:** `mirror_expected_deliveries`.
- **03 §2:** stage `show_card` (default true); site_a `pending.show_card: false`.
- **F08:** consistency includes the new object. **F09:** multi-value `stage`, `GET /api/expected-deliveries` (filters: period), and `skip_call_off_count` on the Call Off flow entry.

## Acceptance criteria
- **F17-AC-01** At demo start (All Dates), Expected Delivery shows the open PO line count from `expected_deliveries_v`, and Total Pipeline shows 482. The two are never summed anywhere.
- **F17-AC-02** Selecting Sampling + QCL Ship + QCL Testing filters the table to those stages, and the card counts don't change. "✕ Clear 3 stages" and three chips appear, and the URL holds `stage=sampling&stage=qc_ship&stage=qc_testing`.
- **F17-AC-03** The Call Off card shows "N skip call-off", with N matching an API count test.
- **F17-AC-04** The metric cards show `Week 41 (2026)` (the last complete week before 12 Oct 2026 is ISO week 41, starting 5 Oct), with M3 green, M6 amber and M7 red, and with `on_time/completed` counts matching `weekly_metrics_v`.
- **F17-AC-05** Selecting ON HOLD + EXPEDITE shows rows carrying either one. Clear tags restores everything. The F10 alert-chip band is gone (FR-09).
- **F17-AC-06** F06 stage agreement stays at 100%, the datagen determinism test passes with the PO lines, and the F05 report counts and week-41 percentages are unchanged.
- **F17-AC-07** Screenshot `docs/screenshots/overview-stages-metrics.png` at 1440×900.
