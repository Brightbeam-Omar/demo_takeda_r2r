# F16 · Overview I: Filter Panel, Presets, Bookmarks, Alert Banners

## Context
This replaces F10's dropdown filters and alert chips with the as-built pattern: an expandable pill-based filter panel that collapses to chips, saved presets, bookmarks, and two full-width alert banners, each opening a list window. See 05 v2 §4 (1)–(2).

## Functional requirements
| ID | Requirement |
|---|---|
| F16-FR-01 | **Filter bar:** `[▴ Filters] [☆ Bookmarked] [⚲ Presets]`. Filters toggles the panel open or closed; the arrow points up when open. State persists in the URL (`filters=open|closed`) |
| F16-FR-02 | **Panel rows:** Type pills (All, Small Molecule, Large Molecule, Peptides). Class pills (All, Consumable, Drug Substance, Unknown). **Unknown** uses the reserved key `unknown`, meaning rows whose class is NULL. It is always shown with its count and is not in the profile (OQ-086). Campaign pills with live counts from the loaded rows, a "Filter campaigns…" search box, a scrollable area of max 3 rows, and a `▤ Dropdown view` toggle that turns the pills into a single "All campaigns" multi-select (view choice in `sessionStorage`). Selecting values within a row is OR. "All" clears that row. Semantics are the same as F10 (OQ-059) |
| F16-FR-03 | **Collapsed chips:** when collapsed with filters active, show one chip per filter: `Type: Small Molecule ×`. Multi-value filters summarise as `Class: 2 classes ×`. Stage and tag selections (F17) also appear as chips. Then `Clear all` |
| F16-FR-04 | **Bookmarks:** a star on each table row toggles a bookmark for the current user (`POST/DELETE /api/bookmarks/{row_key}`). New table `bookmark(user_key, row_key, created_at)`, PK (user_key, row_key). Any persona, including viewer, may bookmark; bookmarks are personal and not audited (OQ-091). `☆ Bookmarked` is greyed until the user has ≥ 1 bookmark. When active it filters to the user's bookmarks (URL `bookmarked=1`). The keyboard shortcut **B** toggles the focused row (F18) |
| F16-FR-05 | **Presets:** a menu listing the user's saved presets ("No saved presets" when empty) plus `+ Save current filters` (name prompt). A preset stores the filter query string (type, class, campaign, period, stage, tags, q, bookmarked), with `period` stored literally so `this_week` stays relative (OQ-089). New table `filter_preset(id, user_key, name, query, created_at)`, unique (user_key, name). Endpoints `GET/POST/DELETE /api/presets` and `PUT /api/presets/{id}`. A duplicate name returns 409; the UI then asks "Replace existing preset?" and confirming overwrites it through `PUT`. Applying a preset replaces the URL filter state |
| F16-FR-06 | **Adjusted needs-by banner:** "N adjusted needs-by dates (planner overrides, across all stages)" with an outline calendar icon (the SVG of the period button, not an emoji) and `[View details]`. The banner is blue (info) in both states; only the Insights banner turns red. The count is **non-released** rows with a **current** adjusted need-by that pass every filter except stage (OQ-059(5)), including `bookmarked` (OQ-087). Use the singular "1 adjusted needs-by date" when N = 1. When N = 0 it shows the blue empty state "No adjusted needs-by dates in this period" |
| F16-FR-07 | **Adjusted Needs-by Dates window:** title "Adjusted Needs-by Dates — Planner Overrides". Columns: Batch · Material (code + description beneath) · `<terms.erp>` Date (locked system date) · Adjusted Date · Δ Days (green `+n` when pushed later, red `−n` when pulled earlier) · Reason (label) · Set By (display name). Sorted by the current override version's `created_at`, newest first; Set By is that version's author's `app_user.display_name` (OQ-090). The window toolbar has Export, Search all columns…, Reset Table, pagination and rows per page (the shared `DataTable` from F18; ship a minimal version here and F18 extends it) |
| F16-FR-08 | **Insights banner:** "ⓘ `<terms.insights_banner>` (N batches)" with `[View all N →]`, red when N > 0 and blue "No `<terms.insights_banner>` in this period" when 0. N = air-gap rows passing every filter except stage, including `bookmarked` (OQ-087) |
| F16-FR-09 | **Insights window:** title "`<terms.insights_banner>` — N affected batches". Explanatory line: "Batches where `<terms.lims>` is approved but `<terms.erp>` has not received the result. Flagged after `<air_gap.threshold_hours>`+ hours — each day erodes the QA Release SLA. Sorted worst-first." Columns: Batch · Material · Stage · **Days Gap** = floor(hours / 24) (chip: green < 2, amber 2–5, red > 5, labelled e.g. `1d`, `3d`). Rows under the air-gap threshold are not air gaps and are excluded, so the smallest chip is `1d` (OQ-088). Sorted by gap descending. If F12 is built, a Proposal column shows the agent proposal status (that column is F12's) |
| F16-FR-10 | *Moved to F17-FR-09 (OQ-085).* F16 keeps F10's alert-chip band and inline tag chips; they have no replacement until F17 adds the LATE, REJECTED and ON HOLD tags |

## Contract changes
- **04 §5:** add the `bookmark` and `filter_preset` tables.
- **F09 API:** add the bookmark endpoints (`GET /api/bookmarks`, `POST/DELETE /api/bookmarks/{row_key}`), the preset endpoints (`GET/POST /api/presets`, `PUT/DELETE /api/presets/{id}`), the `bookmarked` overview filter, the reserved `class[]=unknown`, `adjusted_count` and the user's `bookmarks` on the overview response, and `GET /api/overview/adjusted` (the rows for FR-07, honouring filters). The insights list reuses the existing air-gap alert data, extended to every air-gap row (no top-5 cap) through `GET /api/overview/insights`.
