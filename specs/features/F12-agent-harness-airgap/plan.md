## Deviations
- **Replay key per model call (OQ-139, accepted).** FR-03 defines one key per run, `sha256(agent_key + prompt_version + tool results + candidate facts)`. The runner is a multi-turn loop, so a key that includes tool results does not exist until the tools have run and cannot answer the first model call. Instead the key is `sha256(agent_key, prompt_version, turn index, canonical JSON of the message list so far)` per model call, one file per call under `recordings/air_gap/<key>.json`. The message list carries the candidate facts and the earlier tool results, so the content of the original key is still covered. Tools return a whitelisted, stable projection, so the key does not move on reset. Metadata (`model_id`, `recorded_at`, tokens, latency) is stored but is not part of the key. Reason: replay must work call by call in a tool loop.
- **No `temperature` on the model call (F12-FR-02).** FR-02 asks for `temperature=0`. The current `anthropic` SDK (1.11) has no `temperature` parameter on `messages.create` for `claude-sonnet-5-5`, so the call sends `max_tokens=1500`, a 60 s timeout and 2 retries only. Determinism of the demo does not rest on sampling: replay answers every call from a recording (P7), and the validator checks every output.
- **`complete()` has no `response_schema` argument (02-architecture section 4).** The structured output is the final `submit_ticket` tool call whose input schema is `AirGapTicket`, so the gateway needs no schema argument. The gateway also takes the `trace` sink and the turn number, so every provider writes the same request and response trace steps.
- **The replay key also covers the system prompt and the tool specs (OQ-139).** FR-03 names `prompt_version` only. An edit to a prompt file without a version bump would silently replay an answer written for the old prompt, so the key hashes the system text and the tool specs as well. Same reason as the per-call key: a recording is found only for the exact situation it was made in.
- **Prompt files live in the package (FR-05).** FR-05 names `services/agents/prompts/`; they are at `services/agents/src/agents/prompts/air_gap/v1/` so the installed wheel (the compose image) contains them. The user prompt also carries the site numbers (threshold hours, high-priority window, today) as template variables, so the system prompt stays a plain file.
- **`MODEL_ID` check (OQ-146).** Before T2 (2026-10-07) `GET /v1/models/claude-sonnet-5-5` returned 200, display name "Claude Sonnet 5.5": the id in `.env.example` is current. The check before T10 has not been possible: every message call returns "credit balance too low", so T10 (recordings) and F12-AC-08 (live run) wait for credit on the account.
